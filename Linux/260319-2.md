## **1. 사용자/로그인 확인**

### **`who` / `w` / `users` / `logname`**
* **`who`**: 로그인 사용자 확인. 사용자가 로그인할 때 기록되는 `/var/run/utmp` 파일을 참고합니다.
* **`w`**: 로그인 상태 확인. 시스템에 로그인한 사용자의 상태를 출력합니다. (`/var/run/utmp` 파일 참고)
  * `14:17:32` (현재 시간), `up 14 min` (시스템 가동 시간), `1 user` (현재 로그인 사용자 수)
  * `load average`: 최근 1분, 5분, 15분 평균 부하 (`/proc/loadavg`)
* **`users`**: 시스템에 로그인한 사용자의 목록(이름) 정보를 출력합니다.
* **`logname`**: 로그인한 사용자의 이름을 출력합니다.

```bash
$ who
linuxadmin pts/0        2026-03-19 14:02 (192.168.100.1)

$ w
 14:17:32 up 14 min,  1 user,  load average: 0.00, 0.00, 0.00
USER     TTY        LOGIN@   IDLE   JCPU   PCPU WHAT
linuxadm pts/0      14:02    1.00s  0.05s  0.00s w

$ users
linuxadmin user1
$ logname
linuxadmin
```

### **`last` / `lastb` : 로그인 성공/실패 기록**
* **`last`**: 로그인 기록. 정상적으로 로그인을 하거나 재부팅하면 그 정보를 `/var/log/wtmp` 파일에 저장합니다. (data 파일이므로 cat으로 확인 불가)
* **`lastb`**: 실패 기록. 로그인 실패를 기록하고 확인할 수 있으며 보안 점검에 자주 사용됩니다. (`/var/log/btmp` 에 바이너리 형태로 저장, root 권한 필요)

```bash
$ last
user1    pts/1        192.168.100.1    Thu Mar 19 14:30   still logged in  
linuxadm pts/1        192.168.100.1    Thu Mar 19 14:03 - 14:10  (00:07)
linuxadm pts/0        192.168.100.1    Thu Mar 19 14:02   still logged in
reboot   system boot  5.14.0-611.5.1.e Thu Mar 19 14:02   still running

# btmp 파일 초기화 (sudo 명령어는 리다이렉션을 이용해 0byte 초기화가 불가능하므로 /dev/null 복사 활용)
$ sudo cp /dev/null /var/log/btmp

$ sudo lastb
testuser ssh:notty    192.168.100.3    Thu Mar 19 15:17 - 15:17  (00:00)
testuser ssh:notty    192.168.100.3    Thu Mar 19 15:17 - 15:17  (00:00)
btmp begins Thu Mar 19 15:17:04 2026
```

## **2. 사용자 및 그룹 관리**

### **`useradd` / `usermod` / `userdel`**
* **`useradd`**: 사용자 추가. 생성 후 비밀번호를 설정해야 로그인할 수 있습니다.
  * 사용자의 정보는 `/etc/passwd`(사용자 정보), `/etc/group`(그룹 정보) 에 추가되며 이 두 파일은 일반 유저도 볼 수 있습니다.
  * 비밀번호 정보는 `/etc/shadow`, `/etc/gshadow` 에 추가되며 일반 유저는 권한이 없어서 볼 수 없습니다.
  * 사용자의 홈 디렉터리가 `/home/` 밑에, 메일함이 `/var/spool/mail` 에 생성됩니다.
* **`usermod`**: 사용자 수정. (vi 기반으로 변경할 때는 `vipw` 사용)
* **`userdel`**: 사용자 삭제. (`-r` 옵션은 홈 디렉터리와 메일 스풀 삭제)

```bash
$ sudo useradd user1
$ sudo passwd user1

# 사용자 셸 정보 수정 및 vipw 사용 (일반 vi는 사용하지 말자!!!)
$sudo usermod -s /bin/sh user3$ sudo vipw  # sudo vi /etc/passwd

$ sudo userdel -r user1
```

### **`groupadd` / `groupmod` / `groupdel` / `gpasswd`**
* **`groupadd`**: 그룹 추가. (`/etc/group`, `/etc/gshadow`에 추가됨) 사용자를 생성할 때 특정 그룹에 포함되어 있다는 정보가 저장되는 것이지 그룹 자체가 추가되지는 않습니다. 그룹 ID보다 이름으로 접근하므로 이름이 중요합니다.
* **`groupmod`**: 그룹 수정. (`-g`: GID 변경, `-n`: 그룹명 변경)
* **`groupdel`**: 그룹 삭제. 없는 그룹 사용 시 에러 메시지는 Standard Error(stderr)로 출력됩니다.
* **`gpasswd`**: 그룹 비밀번호/관리

```bash
$ sudo groupadd project1
$ sudo groupadd project3

$sudo groupmod -g 1005 project3   # GID를 1005로 변경$ sudo groupmod -n prj3 project3   # 이름을 prj3로 변경

$ sudo groupdel project1
```

## **3. 계정 만료 설정 (`chage`)**
계정 만료 날짜가 지나면 로그인이 금지됩니다.

### **`chage -E` : 계정 만료 설정**
사용자를 생성할 때나, 생성 후에 계정 만료를 설정할 수 있습니다.

```bash
# 생성 시 만료 설정 (-e 옵션)
$ sudo useradd -e 2026-05-01 user2

# 생성 후 만료 설정 (-E 옵션)
$sudo chage -E 2026-05-01 user1$ sudo chage -l user1
# ...
# Account expires : May 01, 2026  <--
```

### **`chage -I` : 비밀번호 유예 기간 설정**
비밀번호 유예 기간이란 비밀번호 최대 일자가 끝난 후 변경할 수 있는 기간을 말합니다.
* `-M` : 비밀번호 최대 사용 기간 (보통 30일, 60일, 90일 정도로 설정)
* `-I` : 만료 후 비밀번호 비활성화 유예 기간

```bash
$sudo chage -M 2 user3$ sudo chage -I 5 user3

$ sudo chage -l user3
Last password change                                    : Mar 19, 2026  <-- 비번 변경 날짜
Password expires                                        : Mar 21, 2026  <-- Last password change + Maximum number 
Password inactive                                       : Mar 26, 2026  <-- Password expires + 5일 유예기간
Maximum number of days between password change          : 2   <-- 30일, 60일, 90일 정도에서 설정한다.
```
