### **웹 애플리케이션에 필요한 기술들**

**1. 프로그래밍**
* **HTML**: 태그를 이용해서 웹페이지를 생성하는 언어
* **CSS**: HTML의 내용을 좀 더 화려하게 보여주는 스타일과 레이아웃을 정의하는 스타일 시트 언어
* **JavaScript**: 클라이언트에서 HTML의 정적인 환경을 동적인 환경으로 변환해주는 프론트엔드용 언어
* **PHP**: Unix, Linux, Window 서버에서 사용하는 백엔드용 웹프로그래밍 언어
* **JSP**: Unix, Linux, Window 서버에서 사용하는 백엔드용 웹프로그래밍 언어
* **ASP**: Window 서버에서 사용하는 서버에서 백엔드용 웹프로그래밍 언어
* **Spring FrameWork**: 자바를 기반으로 하는 서버에서 백엔드용 언어 

**2. 서버 환경**
* **APM + Tomcat 환경**: Apache + PHP + MySQL or MariaDB + Oracle + Java + Apache Tomcat
* **LAMP**: Linux + Apache + MySQL or MariaDB + PHP
* **LEMP**: Linux + Enginx + MySQL or MariaDB + PHP

**3. 개발자 PC 환경**
* **APM + Java + Tomcat 환경**
  - Apache + PHP + MySQL or MariaDB + Oracle + Java + Tomcat + Eclipse + VSCode + Oracle sqldeveloper

**4. 용어**
* **Apache 웹서버**: 웹 문서(정적 웹페이지)를 전달하는 역할을 하는 서버
* **PHP**: 웹 문서(동적 웹페이지)를 만드는 프로그래밍 언어
* **MariaDB**: 데이터를 저장하는 DBMS(DataBase Management System) 서버
* **Oracle**: 데이터를 저장하는 DBMS 서버
* **Java**: 자바 프로그래밍 언어
* **Eclipse, IntelliJ**: JAVA, JSP IDE 환경의 개발 도구
* **VSCode**: 다양한 프로그래밍 언어의 개발 에디터 
* **sqldeveloper**: 오라클 DB 클라이언트

### **웹서버 구성 요소**

**Apache/Nginx (웹서버)**
* 정적인 페이지를 클라이언트에게 전송하는 역할을 한다.
* 동적인 페이지는 생성하지 못하기 때문에 PHP가 필요하다.
* DBMS처럼 자료 저장을 못하기 때문에 DBMS가 필요하다.
* 공식사이트: https://httpd.apache.org/
* 최신버전: 2.4.66 (2026.3.21 기준)

**Php (웹프로그래밍 언어)**
* 동적인 웹페이지를 생성한다.
* 외국에서는 PHP를 많이 사용하고 선호한다.
* 파일로 데이터를 저장할 수 있지만 DBMS처럼 전문적으로 데이터를 체계적으로 저장하지는 못한다. 그러므로 DBMS가 필요하다.
* 공식사이트: https://www.php.net/
* 최신버전: 8.5.4 (2026.3.21 기준)

**MariaDB (데이터베이스 서버)**
* 데이터를 체계적으로 저장하는 서버.
* 웹/애플리케이션에서 연동해서 자료를 저장하는 서버로 많이 사용한다.
* 공식사이트: https://mariadb.org/, https://mariadb.com/
* 최신버전: 다양한 버전이 존재한다. (2026.3.21 기준 / Latest releases: 12.3.1 RC, 12.2.2, 11.8.6, 11.4.10, 10.11.16, 10.6.25)

### **4. MariaDB 설정 파일 수정**

**옵션의 의미**
* `[mysqld]` : MySQL 서버 프로세스(mysql)에 적용한다는 의미이다.
* `datadir=/var/lib/mysql` : MySQL/MariaDB의 데이터 저장 디렉터리를 설정한다.
* `socket=/var/lib/mysql/mysql.sock` : 로컬에서 MySQL/MariaDB 에 접속할 때 사용하는 유닉스 소켓 파일 경로를 의미한다.
* `symbolic-links=0` : 심볼릭 링크 사용을 비활성화(데이터 파일 접근 시 심볼릭 링크를 따라가지 않도록 하는 설정)한다.
* `collation-server=utf8_general_ci` : 서버의 기본 정렬 규칙(Collation) 을 utf8_general_ci 로 설정한다.
* `character-set-server=utf8` : 서버의 기본 문자셋(Character Set) 을 utf8 로 설정한다.
* `skip-character-set-client-handshake` : 클라이언트가 접속하면서 요청하는 문자셋을 무시하고 서버가 지정한 문자셋 설정을 강제로 사용하게 한다.
* `bind-address=127.0.0.1` : MySQL/MariaDB 서버가 어느 IP 주소에서 접속을 받을지 설정한다.
  * 이 옵션이 없으면 서버에 설정된 모든 IP주소가 바인딩된다.
  * 127.0.0.1 을 설정했으므로 외부에서 접속을 하지 못하고 내부에서만 접속을 하기 위한 설정이다. 외부에서 접속을 하고자 한다면 SSH 터널링을 이용하면 된다.

```bash
[root@victim ~]# vi /etc/my.cnf
```
```ini
[mysqld]
datadir=/var/lib/mysql
socket=/var/lib/mysql/mysql.sock
symbolic-links=0
collation-server=utf8_general_ci
character-set-server=utf8
skip-character-set-client-handshake
bind-address=127.0.0.1

[mysqld_safe]
log-error=/var/log/mariadb/mariadb.log
pid-file=/var/run/mariadb/mariadb.pid

#
# include all files from the config directory
#
!includedir /etc/my.cnf.d
```

### **5. 서버 시작 및 포트 확인**

**명령어 설명**
* `systemctl enable --now httpd.service`
  * Apache 웹 서버(httpd)를 부팅 시 자동 시작되게 설정한다.
  * `systemctl`: systemd 서비스를 관리하는 명령어
  * `enable`: 해당 서비스를 부팅할 때 자동으로 시작되도록 등록 (enable 말고 start, stop, restart, reload 등이 올 수 있다.)
  * `--now`: 지금 즉시 서비스를 시작
  * `httpd.service`: Apache 웹 서버 서비스 유닛 이름 (httpd 로 줄여서 사용할 수 있다.) 
  * `mariadb.service`: MariaDB 서버 서비스 유닛이름 (mariadb 로 줄여서 사용할 수 있다.) 
* `systemctl status httpd.service` : Apache 웹 서버(httpd)의 현재 상태를 확인한다.
* `systemctl status mariadb.service` : MariaDB 데이터베이스의 현재 상태를 확인한다.

```bash
[root@victim ~]# systemctl enable --now httpd.service
[root@victim ~]# systemctl enable --now mariadb.service
[root@victim ~]# systemctl status httpd.service
[root@victim ~]# systemctl status mariadb.service
```

**서비스의 열린 포트를 확인한다.**
* **22/tcp**: Secure Shell (SSH) Protocol 원격 접속(암호화 전송). 전송하는 데이터를 중간에 도청(Sniffing)해도 원본을 볼 수 없기 때문에 보안에 강하다.
* **25/tcp**: Simple Mail Transfer Protocol 메일 전송
* **80/tcp**: HyperText Transfer Protocol WorldWideWeb HTTP.
  * 평문 전송이므로 전송하는 데이터를 중간에 도청(Sniffing)하면 노출되므로 보안에 취약하다.
  * 예전에는 개인정보가 전송이 되지 않는 구간에는 암호화를 하지 않았다. 이유는 암호화(양방향)를 하면 복호화를 해야 하므로 느리기도 했지만 법에 들어있지 않았던 시절이었다. 하지만 개인정보를 저장한 서버들은 반드시 암호화해서 만들어야 하는 서버인 보안 서버를 무조건 구축해야 하는 것이 법에 명시되어 있기 때문에 반드시 https를 사용해야 한다.
  * 만약 개인정보를 저장하는 서버에서 https를 구축하지 않으면 어떻게 될까? 서버를 구축할 수 있는 기간을 주고 그 기간 안에 구축을 해야 한다. 만약 그 기간이 지났는데도 구축을 하지 않으면 과태료가 부과된다.
  * 참고: `/etc/shadow` 파일에는 비밀번호가 암호화되어서 저장된다. 비밀번호가 암호화되는 것은 일방향 암호화이므로 해시 함수가 그 암호화를 해준다. 복호화는 안된다.
* **443/tcp**: http protocol over TLS/SSL 를 사용하는 https 이다.
  * 아파치 웹서버를 사용하면 `mod_ssl` 패키지가 https 를 지원하는 패키지이다.
  * 인증서를 통해서 데이터를 암호화하므로 데이터를 중간에 도청(Sniffing)해도 원본을 볼 수 없기 때문에 보안에 강하다.
* `/etc/services`: 포트에 대한 정보가 저장된 파일 (참고: https://www.iana.org/assignments/port-numbers)

```bash
[root@victim ~]# netstat -nltp
Active Internet connections (only servers)
Proto Recv-Q Send-Q Local Address           Foreign Address         State       PID/Program name
tcp        0      0 0.0.0.0:22              0.0.0.0:* LISTEN      1003/sshd
tcp        0      0 127.0.0.1:25            0.0.0.0:* LISTEN      1251/master
tcp        0      0 127.0.0.1:3306          0.0.0.0:* LISTEN      11514/mysqld  <--
tcp6       0      0 :::22                   :::* LISTEN      1003/sshd
tcp6       0      0 ::1:25                  :::* LISTEN      1251/master
tcp6       0      0 :::443                  :::* LISTEN      11596/httpd   <--
tcp6       0      0 :::80                   :::* LISTEN      11596/httpd   <--
```

**방화벽 포트 허용 설정**
