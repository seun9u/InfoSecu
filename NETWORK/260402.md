## **실습. [LAB] OSPF Area 개념 이해: 회사 조직 비유 🏢**

거대한 네트워크를 하나로 묶어 관리하면 효율이 크게 떨어집니다.
마치 큰 회사가 본사와 여러 부서로 조직을 나누어 관리하듯, **OSPF 네트워크도 'Area(구역)' 단위로 분리하여 효율적으로 관리**합니다.



---

### **1. OSPF 핵심 개념과 회사 조직 비유**

* **OSPF AS (회사 전체)**: 하나의 거대한 네트워크 도메인 전체
* **OSPF Area (각 부서)**: 네트워크를 효율적으로 관리하기 위해 나눈 구역 (영업부, 인사부 등)
  * *분리 이유*: 모든 라우터가 전체 네트워크 정보를 다 가지면 부담이 큽니다. 한 부서 직원이 타 부서의 세부 업무까지 알 필요 없는 것과 같은 이치입니다.

### **2. OSPF 구성 요소별 역할 요약표**

| OSPF 구성 요소 | 회사 조직 비유 | 주요 역할 및 특징 |
| :--- | :--- | :--- |
| **Area 0** (Backbone) | **본사 / 중앙본부** | 모든 부서(Area)를 연결하는 핵심 통제 조직 |
| **Internal Router** | **부서 내부 직원** | 자신이 속한 Area 내부의 상세 토폴로지만 알고 있음 |
| **ABR** (Area Border Router) | **부서장 / 연락 담당자** | 자기 부서(Area)와 본사(Area 0)를 연결. 라우팅 정보를 요약해 전달 |
| **ASBR** (AS Boundary Router) | **외부 협력 담당자** | 타 회사/망 등 OSPF 외부 네트워크(Static, RIP, BGP 등) 정보를 OSPF로 재분배 |
| **LSDB** (Link-State DB) | **부서 내부 조직도** | 해당 Area 내부의 세부 연결/업무 흐름 지도 |
| **LSA** (Link-State Adv.) | **사내 공지문** | 구조 변경, 신규 네트워크 생성 등의 변경 사항을 전파 |
| **SPF** (Shortest Path First) | **최적 보고 라인 계산** | 가장 빠르고 효율적인 데이터 전달(보고) 경로를 계산하는 알고리즘 |

---

### **3. Area 0 (백본) 연결 원칙과 Virtual Link**

OSPF 설계의 절대 원칙: **모든 일반 Area(부서)는 반드시 Area 0(본사)과 직접 연결되어야 합니다.**

#### ❌ **잘못된 연결 구조 (일렬 연결)**
`[Area 4] - [Area 3] - [Area 2] - [Area 0]`
* **문제점**: 물리적 연결은 가능하지만, 논리적으로는 OSPF 원칙 위배입니다. Area 3과 Area 4는 본사(Area 0)와 직접 연결된 창구가 없어 관리가 불가능합니다.

#### ⭕ **올바른 연결 구조 (Star Topology)**
각 부서가 본사와 직접 창구를 가지는 형태가 가장 이상적입니다.
```text
       [Area 3] - [Area 0] - [Area 2]
                     |
                  [Area 4]
```

#### 💡 **해결책: Virtual Link (가상 링크)**
불가피하게 `[Area 3] - [Area 2] - [Area 0]` 형태로 연결된 경우, **Virtual Link**를 사용해 해결할 수 있습니다.
* **개념**: Area 3가 Area 2를 통과하는 '가상의 통로'를 뚫어 Area 0과 논리적으로 직접 연결된 것처럼 만드는 기술입니다.
* **주의사항**: 임시방편이자 복구용 기술이므로 **설계가 복잡해지고 운영상 부담**이 커집니다. 실무에서는 정석 설계로 권장하지 않으며, 모든 Area가 Area 0을 중심으로 연결되는 것이 원칙입니다.
