# 🌐 스위치 IP 설정 및 정적 라우팅(Static Routing) 핵심 정리

## 1. 스위치 유형별 IP 주소 설정 방식

스위치는 모델에 따라 IP를 설정하는 위치와 방식이 다릅니다.

### 📍 L2 스위치 (관리용 IP 설정)
* **특징**: 물리 포트가 L2 포트이므로 포트 자체에 IP를 설정할 수 없습니다.
* **설정**: SVI(Switch Virtual Interface)라는 가상 인터페이스에 IP를 설정합니다.
    * **VLAN 1(기본)**: `en` > `conf t` > `int vlan 1` > `ip address [IP] [마스크]`
    * **기타 VLAN**: `vlan 10` 생성 후 `int vlan 10`에서 동일하게 설정합니다.
* **외부 통신**: 스위치 자체가 외부 네트워크와 통신하려면 게이트웨이가 필요합니다.
    * `en` > `conf t` > `ip default-gateway [게이트웨이IP]`

### 📍 L3 스위치 (포트 및 VLAN 설정)
* **포트 IP 설정**: 기본 L2 포트를 L3로 변경해야 합니다.
    * `en` > `conf t` > `int fa0/1` > **`no switchport`** > `ip address [IP] [마스크]`
* **VLAN IP 설정**: L2와 마찬가지로 SVI에 설정 가능합니다.
    * `en` > `conf t` > `int vlan 1` > `ip add [IP] [마스크]` > `no sh`
* **게이트웨이**: 동일하게 `ip default-gateway` 설정을 사용합니다.

## 2. 실습.[LAB] 정적 라우팅(Static Routing) 설정하기

### 📍 문제 분석: Ping 통신 실패 원인
PC1에서 1.1.1.2로 핑을 보냈으나 `Request timed out`이 발생하는 경우입니다.

1. **패킷 전송 (PC1 -> R1 -> R2)**: R1은 목적지(1.1.1.0/30)가 직접 연결되어 있어 R2로 패킷을 보냅니다.
2. **패킷 폐기 (R2)**: R2가 응답(Reply)을 보내려 할 때, 목적지인 `10.10.10.0/24` 네트워크가 자신의 라우팅 테이블에 없어 **R2에서 패킷이 버려집니다.**



### 📍 해결 방법: 정적 라우팅 설정
관리자가 모르는 네트워크 정보를 수동으로 등록합니다.

* **설정 형식**: `ip route [목적지네트워크] [마스크] [넥스트홉IP 또는 인터페이스]`
* **R2 설정 예시**:
  ```ios
  R2(config)# ip route 10.10.10.0 255.255.255.0 1.1.1.1
  ```
* **삭제 방법**: 반드시 서브넷 마스크까지 정확히 입력해야 합니다.
  ```ios
  R2(config)# no ip route 10.10.10.0 255.255.255.0
  ```

## 3. 라우팅 테이블(Routing Table) 상세 분석



### 📍 테이블 항목 읽는 법
`S 10.10.10.0/24 [1/0] via 1.1.1.1`
* **S (Static)**: 관리자가 수동으로 등록한 경로입니다.
* **10.10.10.0/24**: 패킷이 찾아갈 목적지 네트워크 대역입니다.
* **[1/0] (AD/Metric)**:
    * **AD(Administrative Distance)**: 신뢰도(우선순위)입니다. 정적 라우팅은 **1**로 매우 높습니다.
    * **Metric**: 경로의 비용(거리)입니다.
* **via 1.1.1.1**: 다음 홉(Next Hop) 주소로, 이 패킷을 전달할 다음 관문입니다.

### 📍 직접 연결된 경로 (C & L)
* **C (Connected)**: 해당 네트워크가 특정 인터페이스에 직접 연결되어 있음을 의미합니다.
* **L (Local)**: 라우터 자신의 인터페이스에 설정된 **단일 IP 주소**입니다.
    * **프리픽스 `/32`**: 오직 자기 자신의 IP 주소 하나만을 의미합니다.
    * **참고**: 프리픽스(Mask) 길이가 없으면 그것이 네트워크 주소인지 단일 IP인지 알 수 없습니다. (예: `1.1.1.128/25`는 네트워크 주소이지만, `1.1.1.128/32`는 단일 IP 주소입니다.)
