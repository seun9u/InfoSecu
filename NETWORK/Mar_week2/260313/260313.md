## ACL (Access Control List) 개요 및 필요성

Network #1의 관리자만 R1 라우터나 SW1 스위치에 접근해야 하는데, 다른 네트워크(Network #2)에서 불법으로 접근하게 되면 보안상 큰 문제가 발생합니다. 이렇게 특정 트래픽의 접근을 허용하거나 차단(거부)하여 운명을 결정하는 기능이 바로 **ACL**입니다.      


---

## 실습.[LAB] R1 라우터에서 SSH 접근 제어 설정하기

### 1. 조건 분석 및 와일드카드 마스크 계산
* **네트워크 대역**: `192.168.100.0/26`
* **서브넷 마스크**: `255.255.255.192` (11111111.11111111.11111111.11000000)
* **와일드카드 마스크**: `0.0.0.63` (00000000.00000000.00000000.00111111)
  * *참고*: 와일드카드 마스크는 서브넷 마스크의 0과 1을 반전시킨 값입니다.

### 2. ACL 설정 문법
Telnet이나 SSH 접속은 `vty line`을 통해 이루어지므로, 작성한 ACL을 반드시 `vty line`에 적용해야 합니다.

* **특정 호스트(1대) 지정**: `host` 키워드 사용 (또는 생략 가능)
  * `access-list <ACL#> host <IP address>`
  * `access-list <ACL#> <IP address>`
* **네트워크 대역 지정**: 와일드카드 마스크 사용
  * `access-list <ACL#> <IP address> <wildcard mask>`

### 3. R1 라우터 ACL 설정 스크립트
```ios
! R1 라우터 설정
en
conf t
 ! 특정 호스트(192.168.100.2 및 192.168.100.4)만 허용하는 ACL 10번 생성
 ! access-list 10 permit 192.168.100.2 0.0.0.63 (네트워크 전체 허용 시)
 access-list 10 permit host 192.168.100.2
 access-list 10 permit 192.168.100.4
 
 ! vty 라인에 ACL 적용
 line vty 0 4
 access-class 10 in
 end
wr
```

#### 📍 설정 확인 및 테스트
```ios
! ACL 목록 확인 명령어
R1#sh access-lists
Standard IP access list 10
    10 permit host 192.168.100.2
    20 permit host 192.168.100.4
```
* **PC1 접속 시도**: `ssh -l admin 192.168.100.1` → **접속 허용** (Password 입력 창 뜸)
* **PC2 접속 시도**: `ssh -l admin 192.168.100.1` → **접속 거부** (`% Connection refused by remote host`)

---

### 4. ACL 생성 및 삭제 순서 (중요)

**📍 올바른 생성 순서**
1. ACL 목록 생성 (`access-list ...`)
2. VTY 라인에 추가 (`access-class ... in`)
3. ACL 목록 확인 (`sh access-lists`)
4. VTY 라인 확인 (`sh run | section vty`)
5. SSH 접속 테스트 (허용/거부 확인)

**📍 올바른 삭제 순서**
1. VTY 라인에서 제거 (`no access-class 10 in`)
2. ACL 목록 삭제 (`no access-list 10`)
3. ACL 목록 확인
4. VTY 라인 확인
5. SSH 접속 테스트 (모두 접속 허용됨을 확인)

## 실습.[LAB] ACL 추가/삭제 특징 확인

### 1. ACL 항목 순차적 추가
```ios
R1(config)#access-list 1 permit 1.1.1.1
R1(config)#access-list 1 permit 1.1.1.2
R1(config)#access-list 1 permit 1.1.1.3
R1(config)#access-list 1 permit 1.1.1.4
R1(config)#access-list 1 permit 1.1.1.5

R1(config)#do sh access-lists
Standard IP access list 1
    10 permit host 1.1.1.1
    20 permit host 1.1.1.2
    30 permit host 1.1.1.3
    40 permit host 1.1.1.4
    50 permit host 1.1.1.5
```

### 2. ACL 삭제 시 주의점
Standard ACL의 경우, 특정 줄(예: `1.1.1.5`) 하나만 삭제하려고 `no` 명령어를 사용하면 **해당 번호의 전체 목록이 삭제**되는 특징이 있습니다.
```ios
! 50번 항목 하나만 지우려고 시도
R1(config)#no access-list 1 permit 1.1.1.5

! 확인 결과: access-list 1번 자체가 모두 삭제됨
R1(config)#do sh access-lists
```
