# 🌐 VTP (VLAN Trunking Protocol) 핵심 정리

## 1. VTP 개요 및 필요성
VTP는 시스코 스위치 간에 VLAN 정보를 자동으로 공유하여 관리의 편의성을 높여주는 프로토콜입니다.

* **사용 이유**: 스위치가 여러 대(예: 10대 이상)일 때, 모든 스위치에서 일일이 VLAN을 생성/수정/삭제하는 번거로움을 줄이기 위함입니다.
* **장점**: VTP Server 1대에서만 VLAN을 관리하면, 동일 도메인 내의 Client 스위치들에 VLAN 정보가 자동으로 전파되어 관리가 효율적입니다.



---

## 2. VTP 동작을 위한 필수 조건
VTP가 정상적으로 동작하여 정보를 공유하려면 아래 4가지 조건이 일치해야 합니다.
1. **VTP Version**: 모든 스위치가 동일한 버전으로 설정되어야 함.
2. **VTP Domain Name**: 동일한 도메인 이름을 사용해야 함.
3. **VTP Password**: 비밀번호 설정 시 모든 스위치가 동일해야 함.
4. **Trunk Link**: 스위치 간 연결 포트가 반드시 **Trunk** 모드여야 함.

---

## 3. VTP의 3가지 주요 모드 비교

| 구분 | VTP Server (대장) | VTP Client (쫄병) | VTP Transparent (독립) |
| :--- | :--- | :--- | :--- |
| **VLAN 관리** | 생성, 수정, 삭제 가능 | **직접 관리 불가능** | 직접 관리 가능 (독립적) |
| **정보 전파** | 광고(전파) 수행 | 서버 정보를 받아 적용 및 전달 | 서버 정보를 적용 안 함 (전달만 함) |
| **동기화** | 동기화의 기준점 (Revision) | 서버 정보와 동기화 수행 | **동기화 하지 않음** |
| **특징** | VLAN 정보가 NVRAM에 저장됨 | VLAN 정보가 저장되지 않음 (RAM) | 자신만의 VLAN 정보를 NVRAM에 저장 |

---

## 4. 상세 모드 설명

### 📍 VTP Server
* VLAN 정보를 중앙 관리하는 스위치입니다.
* VLAN 생성/수정/삭제 시 **Configuration Revision** 번호가 1씩 증가하며, 이 정보를 다른 스위치에 광고합니다.

### 📍 VTP Client
* 서버가 보내준 VLAN 정보를 그대로 받아 자신의 스위치에 적용합니다.
* 서버가 VLAN을 삭제하면 클라이언트에서도 자동으로 삭제됩니다.
* 단독으로 VLAN을 관리할 수 없으며, 서버의 지시를 따르는 역할입니다.

### 📍 VTP Transparent (투명 모드)
* VTP 도메인에 속해는 있지만, 서버의 VLAN 정보를 무시하고 독자적으로 운영됩니다.
* 서버가 보낸 VTP 광고 패킷을 자신은 적용하지 않고 다음 스위치로 **전달(Forwarding)**만 해줍니다.

---

## 5. 실무에서의 VTP 운영 (Transparent의 중요성)
실무에서는 VTP를 무조건 사용하기보다 **Transparent 모드**를 선호하는 경우가 많습니다.

* **사고 방지**: VTP Server/Client 구조에서는 Revision 번호가 높은 스위치가 잘못 연결될 경우, 기존의 모든 VLAN 정보가 덮어씌워져 네트워크가 마비될 위험이 있습니다.
* **독립 관리**: 각 스위치별로 필요한 VLAN만 직접 생성하여 관리하는 것이 보안 및 안정성 측면에서 유리할 수 있습니다.
* **결론**: 자동화의 편리함(Server/Client)보다 데이터 안정성(Transparent)을 우선시하는 실무 환경이 많으므로 상황에 맞는 선택이 필요합니다.
