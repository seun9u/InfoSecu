### **2. DBMS 서버 직접 접속**
일반적으로 DBMS는 중요한 서버이므로 보안상 외부에 오픈하지 않는다.
반대로 웹을 제공하는 서버의 포트는 외부에 오픈을 해야 클라이언트가 접속할 수 있다.
또한 실무에서는 8080/tcp 는 직접 제공하지 않고 웹포트(80/tcp, 443/tcp)를 연동해서 제공한다.
외부에서 직접적으로 DBMS(Oracle) 포트(1521/tcp)로 접속할 수 없지만 
여기서 연습이므로 일단 1521/tcp로 연결을 허용한 후 막는 것으로 한다.

**1521/tcp 포트로 직접 접속 허용하기**
```bash
[root@victim ~]# firewall-cmd --permanent --add-port=1521/tcp
[root@victim ~]# firewall-cmd --reload
[root@victim ~]# firewall-cmd --list-all
public (active)
  target: default
  icmp-block-inversion: no
  interfaces: ens33
  sources:
  services: http https ssh
  ports: 8080/tcp 1521/tcp
  protocols:
  masquerade: no
  forward-ports:
  source-ports:
  icmp-blocks:
  rich rules:
```

  . 첫 번째 방법

  . 두 번째 방법
    - sql Developer에서 ssh 터널링을 이용해서 연결하는 방법
    - [메뉴] > [보기] > [SSH]

**첫 번째 방법으로 연결하기 (SSH 터널링을 사용해서 접속하는 방법)**
```text
         SSH Tunnel
       --------------->
[Client]-------------[DBMS Server]------[DB Server]
                         ----------------->
                           localhost
```
       
Host OS(Windows 일 때)의 아래 명령어를 사용해서 `1522/tcp` 포트를 사용하지 않는지 확인해야 한다.
만약 1522/tcp 포트가 사용중이면 쓰지 않는 다른 포트를 선택한다.

### **4. 터널링 사용자 생성**
SSH 터널링을 연결할 `tunneluser` 사용자를 생성한다.   
  . **문제점**: 사용자 생성 후에 `/bin/bash` 셸을 사용할 수 있게 설정했기 때문에 서버에 직접 접속이 된다.
  . **해결 방안**: `/bin/bash` 제거, 비밀번호 최대 사용기간 설정, 계정 만료 기간 설정

**!!! 문제점 상황 확인 !!!** ```bash
[root@victim ~]# useradd -g users tunneluser
[root@victim ~]# passwd tunneluser    
[root@victim ~]# LANG=C chage -l tunneluser

Password expires                                        : never  <-- Last password change + Last password change
Password inactive                                       : never
Account expires                                         : never  <--
Minimum number of days between password change          : 0

Number of days of warning before password expires       : 7
  
[root@victim ~]# grep tunneluser /etc/passwd
tunneluser:x:1002:100::/home/tunneluser:/bin/bash
```

**윈도우의 파워셸에서 실행 테스트 (옵션 없이 실행 시 문제점)** **명령어 옵션 설명**
  . `ssh -L 1522:localhost:1521 tunneluser@192.168.100.10 -f -N`
    - `ssh -L` : 로컬 포트 포워딩
    - `1522`: Local port
    - `localhost`: 자기 자신
    - `1521`: Remote port 
    - `tunneluser@192.168.100.10`: 서버의 사용자
    - `-f -N`: 백그라운드 프로세스로 실행

**해결: 사용자 정보를 삭제하고 제한된 설정으로 다시 생성한다.**
```bash
[root@victim ~]# userdel -r tunneluser
```

**명령어 옵션**
  . `useradd` 
    - `-e, --expiredate EXPIRE_DATE` : expiration date of the new account
    - `-s, --shell SHELL` : login shell of the new account
  . `passwd`
    - `-e, --expire` : expire the password for the named account (root only)
    - `-x, --maximum=DAYS` : maximum password lifetime (root only)
  . `chage`
    - `-E, --expiredate EXPIRE_DATE` : set account expiration date to EXPIRE_DATE
    - `-M, --maxdays MAX_DAYS` : set maximum number of days before password
    
```bash
[root@victim ~]# useradd -e 2026-12-25 -s /bin/false tunneluser  
[root@victim ~]# passwd tunneluser
[root@victim ~]# chage -M 90 tunneluser

[root@victim ~]# LANG=C chage  -l tunneluser
Last password change                                    : Mar 22, 2026
Password expires                                        : Jun 20, 2026
Password inactive                                       : never
Account expires                                         : Dec 25, 2026

Maximum number of days between password change          : 90

### **5. 백그라운드 포트 포워딩 실행 (-f -N)**

**`-f -N` 이 없는 상태**
  . 서버로 접속은 되지만 셸은 사용할 수 없는 상태(`/bin/false`) 이므로 즉시 로그아웃이 된다.
```powershell
PS C:\Users\Administrator> ssh -L 1522:localhost:1521 tunneluser@192.168.100.10
tunneluser@192.168.100.10's password:
Last login: Sun Mar 22 15:36:51 2026 from 192.168.100.1
Connection to 192.168.100.10 closed.  
```
  
**`-f -N` 옵션을 사용하는 올바른 방법**
  . 서버로 접속하는 것이 아니라 포트만 포워딩 시킬 수 있도록 백그라운드로 실행한다.
  . 연결되면 powershell 창은 포워딩 역할을 수행하며 백그라운드로 넘어간다.
```powershell
PS C:\Users\Administrator> netstat -na|findstr 1522
PS C:\Users\Administrator> ssh -L 1522:localhost:1521 tunneluser@192.168.100.10 -f -N
tunneluser@192.168.100.10's password:   
```

### **6. 프로세스 확인 및 종료 (터널링 끄기)**

다른 powershell 창을 열어서 열린 포트를 확인한다.
`1522/tcp` 포트가 열려있다는 것은 프로세스가 실행중이라는 의미이다. 프로세스를 확인해보자.

**프로세스 확인/종료 방법**
  . **작업 관리자 열기**
    - `Ctrl + Shift + Esc` 또는 작업 표시줄 우클릭 → 작업 관리자
  . **tasklist**
    - 프로세스를 확인 (특정 프로세스를 확인: `tasklist | findstr <process name>`)
  . **taskkill**
    - 프로세스 종료
    - 사용법: `taskkill /PID 프로세스ID`, `taskkill /IM 프로세스이름`
    - `-F`: 강제 종료(Force)

```powershell
PS C:\Users\Administrator> netstat -na|findstr 1522
  TCP    127.0.0.1:1522         0.0.0.0:0              LISTENING
  TCP    [::1]:1522             [::]:0                 LISTENING    
    
PS C:\Users\Administrator> tasklist | findstr ssh.exe
_ssh.exe                     13548 Console                    1      9,260 K  <-- mobaXterm에서 접속한 ssh
_ssh.exe                     14328 Console                    1      8,752 K  <-- mobaXterm에서 접속한 ssh
ssh.exe                       6376 Console                    1      9,188 K
    
# PID 6376 강제 종료
PS C:\Users\Administrator> taskkill /PID 6376 /F
성공: 프로세스(PID 6376)가 종료되었습니다.

PS C:\Users\Administrator> netstat -na|findstr 1522
PS C:\Users\Administrator> tasklist | findstr ssh.exe    
_ssh.exe                     13548 Console                    1      9,248 K
_ssh.exe                     14328 Console                    1      8,752 K
```
    
서버로 연결된 2개의 mobaXterm 터미널을 종료한다.
```bash
[root@victim ~]# exit
[root@victim ~]# exit
```

프로세스를 다시 확인하면 `_ssh.exe` 가 모두 없어진 것을 확인할 수 있다.
```powershell
PS C:\Users\Administrator> tasklist | findstr ssh.exe
PS C:\Users\Administrator>
```
